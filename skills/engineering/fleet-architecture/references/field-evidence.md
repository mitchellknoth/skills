# Field evidence for the protocols

Single occurrences from the coordinator of a running fleet (snapshot 2026-11-17), kept short and scrubbed of identifiers, customers, addresses, hashes and run numbers. They explain why a protocol exists. They are not measurements, not proof the protocols transfer, and not an audit; the log they come from is one participant's record. Domain-specific lessons live with the seats that learned them in the `fleet-preset` skill's field notes.

| Protocol | Evidence |
|---|---|
| [1 Doors](protocols.md#1-door-classification), [2 Provenance](protocols.md#2-authorization-provenance) | A grant meant for the coordinator alone went to the implementer once. Memory now records it as coordinator-only, and the implementer's persona says every production apply needs the human's own yes. One security seat closed its score with "merging needs the human's yes" because it could not see a merge grant; it declined to assume one. A re-ask for an exact-revision yes after a blanket yes was called toil by the human. |
| [3 Scoring](protocols.md#3-exact-head-scoring-and-delta-re-score) | The implementer was sent other seats' must-fixes and came back for rounds three, four and five; churn drove the "raiser owns the fix" rule. A full-panel PASS landed on a draft whose infrastructure tests never ran because the label was missing; a size-precondition bug (it measured pretty-printed JSON) slipped to the next change. A change claimed 8 passing and 0 failing on a writer test; the re-run said 7 and 1. Once a seat did a full score because the coordinator's "re-anchor only" claim was wrong, and the correction went in the same log. |
| [4 Merge](protocols.md#4-merge-on-green-watcher) | One merge landed at the parent of the tip, before the last commit: the squash was empty and nothing applied. Pinning the head is the guard. Every merge runs under one shared platform identity (the owner's low-friction default; per-agent identities are the recommended target), so "merged by" was identical for the human and the coordinator, and memory later held two contradictory entries about who merged a revert. A change merged over a browser-shard timeout judged unrelated broke the default branch's image build, which pull-request CI skips; all merges were held until the fix landed. A different build change merged on a code-only PASS with four revert triggers written beforehand; the default branch timed out, a trigger fired, and the revert merged on tree equivalence with no rerun. Triggers turned the decision into a lookup. |
| [5 Challenge](protocols.md#5-challenge-before-you-log) | The log recorded a type error as "pre-existing and unchanged"; the implementer showed it came from a function the change itself added and that was absent on the default branch. The hosted run expected to show it had been cancelled during setup and never reached typecheck. The lessons: verify "pre-existing" against the default state, and treat a skipped step as no evidence either way. |
| [6 Routing](protocols.md#6-routing-and-wake-rules) | A self-audit of routing found the coordinator reversing one of its own earlier must-fix closes by re-running a comparison (specialist work done by the router), and one change touching user creation in an identity provider was routed to the data and legal seats only, with no record of why neither security seat was woken. The remedy: record seats woken and omitted, with the reason. |
| [8 Control budget](protocols.md#8-control-budget) | A defensive seat bounced an enum-parity test that read the schema and shared types by pattern. No runtime array existed to compare, so the implementer deleted the test and shipped a one-line change; the seat re-scored shortly after. In a separate review a pattern-over-source test let three of four planted defects survive and was deleted. |
| [Practices 1 Routines](practices.md#1-routines) | Per-change babysitting routines burned the human's usage limit and were banned; the weekday brief flags stuck changes instead. The narrow merge-on-green watcher is the exception. Once a watcher was paused when a peer reported seven integration failures at the armed head; the fix arrived as a new head and the seats re-scored it before the merge. |
| [Practices 2 Source of truth](practices.md#2-one-source-of-truth) | A status table on a page and the project board drifted apart, and agents acted on the stale one. The page became reference only. A per-merge ledger line that had to be filled at merge time was repeatedly backfilled by the advisor with "unrecorded" fields; the human replaced it with one row in the advisor's scoreboard as the merge record. |
| [Practices 3 Coaching](practices.md#3-coaching-a-peer-agent) | A peer agent from another provider stopped to ask about things it could settle itself: whether an old draft overlapped its work (a look at the last commit date answered it) and how to bring its branch up to default state without tripping a local hook (server-side branch update). The peer also caught a flaw in the coordinator's advice (a change's old commits stay reachable, but the branch pointer moves on push) and said it would confirm reachability first. |
