# What this preset chooses, preserves and changes

## Prescriptive choices

One coordination front door; meaningful increments; test-first behavioral work where practical; risk-routed independent acceptance; final-revision evidence; serialized conflicting writes; three-round review escalation; durable next actions; quiet actionable oversight.

## Deliberate reconciliations

- Valid permission and technical readiness are distinct. Every merge-capable entry point uses the same contract, including batch and short-lived routines.
- No universal “scripts may only shrink” rule. Prefer simple maintainable controls, but an explicit safety-preserving addition may be justified. Retire a check only after evaluating its purpose and replacement evidence.
- Unrelated pre-existing debt does not automatically expand scope. A change that activates or worsens an old flaw must account for that interaction.
- No blanket CI retry. Apply the installation's existing policy. Any future bounded exception needs recognized failure classes, immutable input, terminal prior attempts, no ambiguous side effects, a budget and retained diagnostic history.
- No retired deployment mechanism, historical budget, named cloud, fixed cadence, public-site workflow or model choice is embedded here.

These are proposed reusable refinements, not a claim that the live source system has already adopted them. The template path remains separate and does not inherit these choices.

## Before customization

State why the fence exists, what failure it prevents, what currently enforces it and what will prove a replacement preserves its purpose. Keep authority decisions separate from project facts and ordinary memory. Changes to the preset are versioned and regression-tested; installation-specific exceptions remain private and explicit.

## Boundaries

No active automations, accounts, credentials, tool permissions or standing authority are included. Installing this preset is not approval to merge, publish or deploy. It also does not replace repository requirements or platform safety rules.
