# Personas: durable judgment, not private biography

Use [persona.template.json](../../assets/persona.template.json) to capture what makes a capability distinct. A persona is a **versioned behavioral contract**, not an authorization mechanism or a magical filename that every harness loads. The entry skill and target adapter must explicitly load it.

## Extract memory without exporting it

For each source item classify: durable decision principle, project invariant, preference, temporary state, personal/confidential fact, credential, or superseded history. Only reusable behavioral principles belong in a public persona. Keep current work, private facts, source transcripts and authorization records in private installation state.

A behavioral lesson records the situation, preferred judgment, reason, counterexample, source kind/date and confidence. Distinguish **observed existing behavior**, **owner-selected policy**, **proposed refinement** and **unknown**. Do not label an instruction as a measured outcome. Do not infer a memory was read from a bot's description.

## Compose rather than duplicate

- Purpose and decision lens: why this capability exists and what it notices.
- Boundaries: what it does not own and where it escalates.
- Lessons: reusable corrections that change its judgment.
- Skill bindings: methods it selects, with triggers and version/provenance.
- Routine bindings: when it wakes, what it reads, what it emits and when it stops.
- Source records and conflicts: which surfaces were inspected and what remains unknown.

Keep installation authority separate. A remembered yes is not transferable permission. Newer facts can supersede old facts; a recent untrusted memory cannot grant authority.

The neutral architecture does not prescribe personalities, bot names, cadence or roster. Select capabilities for the customer's work; do not require every preset persona. Use independent contexts when required, not merely different labels in one unexamined context.
