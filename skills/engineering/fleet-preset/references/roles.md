# Risk-routed role cards

Roles are capabilities, not mandatory persistent bots. One role can be loaded in the main loop when independence is not required. An independent reviewer must not be the same unexamined implementation context under another label.

| Capability | Distinct question | Invoke when |
|---|---|---|
| Coordinator | Is the requested outcome owned through completion? | Multi-step work / handoffs |
| Principal / implementer | Does the integrated change meet the contract? | Implementation or architecture work |
| QA | Do tests and observed behavior establish done? | Meaningful behavior/verification risk |
| Product / domain | Is this the correct requirement, not just passing mechanics? | Domain behavior or priority change |
| UX | Does rendered behavior match intended experience and reference? | User-visible layout, interaction or brand |
| SRE | Will it operate, deploy, recover and stay within resource constraints? | Runtime, deployment, secrets, cost or recovery |
| Security Blue | Are controls and trust boundaries sound? | Authentication, authorization, sensitive data or supply chain |
| Security Red | What independent abuse case defeats those assumptions? | High-consequence security boundaries |
| Data | Are identity, tenancy, migrations and data invariants preserved? | Schema, access, migration or data ownership |
| Legal/compliance | What claims, obligations and evidence need specialist counsel? | Policies, regulated claims or publication |
| Finance | Are financial facts sourced and decisions separated from execution? | Business finance analysis |
| Oversight | Did the system act on its own findings and avoid repeated waste? | Periodic/ad hoc operational review |

Independent review is selected by risk and installation policy, not by roster size. Missing a required seat blocks the corresponding acceptance claim; self-review is explicitly not equivalent. Legal/finance roles are not authority to provide licensed services or execute transactions.

For UI review, use rendered evidence tied to the version and relevant surfaces. Separate owner taste choices from correctness/accessibility findings. If the user explicitly accepts a scoped residual, preserve that decision without extending it to unrelated risks.
